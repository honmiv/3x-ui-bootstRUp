3x-ui bootstRUp

Автоматизированная настройка 3x-ui с Caddy в роли фронт-прокси и Nginx для сайта-заглушки. VPN, панель, подписки и обычный HTTPS-трафик работают через один домен и порт.

Установка

Автоматическая

curl -fsSL https://raw.githubusercontent.com/honmiv/3x-ui-bootstRUp/master/install.sh | bash

Вручную

git clone https://github.com/honmiv/3x-ui-bootstRUp.git
cd 3x-ui-bootstRUp
./install.sh

Обновление

Обновление файлов скрипта

Автоматически подтянуть актуальные файлы репозитория:

curl -fsSL https://raw.githubusercontent.com/honmiv/3x-ui-bootstRUp/master/update_sources.sh | bash

Полу-ручной вариант:

git fetch origin
git reset --hard origin/master

Обновление панели

Чтобы обновить панель на конкретную версию:

./update 3.3.1

Чтобы обновить панель на последнюю версию:

./update latest

Откат обновления

Если после обновления что-то сломалось:

./rollback_update

Требования

  • ОС: Ubuntu 26.04, Debian 13, CentOS 9.
  • Домен: доменное имя должно указывать на IP-адрес VPS.
  • DNS: A-запись для IPv4 и AAAA-запись для IPv6, если IPv6 выдан провайдером.
  • Порты: `80` и `443` должны быть свободны.
  • Зависимости: установленный `curl`.

Особенности архитектуры

Все обращения: VPN, веб-панель, подписки и сайт-заглушка используют один домен с единым SNI (`sni=domain`). Выпуск и обновление TLS-сертификатов автоматически управляется через Caddy.

  1. Входящий запрос поступает на Caddy (`domain:443`).
  2. Caddy маршрутизирует трафик на inbound 3x-ui (VLESS + TCP + Reality) без терминации TLS.
  3. Если запрос не является клиентским TCP-подключением, он перенаправляется на inbound VLESS + xhttp + Reality.
  4. Если запрос не является xhttp-подключением, TLS по-прежнему не терминируется, и трафик перенаправляется обратно на внутренний порт Caddy.
  5. На внутреннем порту Caddy терминирует TLS. Расшифрованный HTTP-трафик маршрутизируется на панель 3x-ui, подписки или на Nginx:80.

Для систем DPI любой неавторизованный запрос выглядит как стандартное обращение к HTTPS-сайту.

Client / DPI -> Caddy:443 -> VLESS TCP Reality -> VLESS xhttp Reality -> Internal Caddy -> 3x-ui panel / subscriptions / Nginx fallback
Client HTTP -> Caddy:80 -> HTTPS redirect or Nginx fallback

Как работает setup.sh

Проверка окружения и зависимости

  • Проверяет права `root`.
  • Определяет пакетный менеджер (`apt`, `dnf`, `yum`, `pacman`) и ожидает снятия блокировок.
  • Устанавливает недостающие утилиты: jq, openssl, ss, qrencode и другие.
  • Устанавливает Docker и Docker Compose, если они отсутствуют. Для пользователей из РФ настраивает резервное зеркало реестра `dh-mirror.gitverse.ru`.

Генерация конфигурации

  • Подбирает свободные внутренние порты, генерирует X25519-ключи и безопасные URL-пути для панели и подписок.
  • Обрабатывает шаблоны из `templates` и создает рабочие конфигурационные файлы.

Настройка 3x-ui

  • Запускает контейнер 3x-ui и настраивает его через API.
  • Обновляет учетные данные администратора, применяет маршруты, создает inbound-подключения VLESS TCP и xhttp Reality, добавляет VPN-клиента.

Валидация и интеграция

  • Запускает Caddy и ожидает выпуска SSL/TLS-сертификата.
  • Проверяет доступность HTTPS на 443 порту.
  • Получает и декодирует данные подписки, выводит ссылки и QR-коды.
  • Добавляет `/etc/profile.d/3x-ui.sh`, который показывает адрес и учетные данные панели при SSH-входе.

Примечания

  • Перенаправление нецелевого трафика между inbound-ами реализовано через поле `target`, а не через механизм `fallbacks` последних версий 3x-ui.
  • Добавление или удаление inbound-ов требует аккуратной настройки `target`.
  • Удаление `vless+tcp+reality` inbound без добавления inbound с тем же портом потребует правки Caddyfile.
