# Интеграционные тесты обслуживания (Maintenance Test Suite)

В данной директории находятся тесты операций технического обслуживания инфраструктуры **3x-UI BootstRUp**: резервного копирования, миграции и восстановления на другой сервер, перезапуска сервисов, обновления версий компонентов и процедур отката (rollback).

---

## 📋 Состав тестов

| Файл | Операции (`deploy_mode`) | Описание сценария |
|------|--------------------------|-------------------|
| `test_maint_panel_backup_recovery.py` | `backup`<br>`recovery` | 1. Развёртывание исходной панели на `vps-maint-panel` (`maint-panel.test`).<br>2. Создание удалённого бэкапа и загрузка архива в `./backups_panel/`.<br>3. Восстановление панели из архива на **чистый новый контейнер** `vps-maint-recovery` с **новым доменом** `maint-recovery.test`.<br>4. Проверка автозамены домена, доступности 3x-ui и целостности данных. |
| `test_maint_panel_restart.py` | `restart_panel`<br>`restart_server` | 1. `restart_panel`: мягкий перезапуск Docker-контейнеров панели (`3xui`, `caddy`, `nginx-decoy`). | `test_maint_sub_server.py` | `backup_sub`<br>`restart_sub`<br>`update_sub`<br>`rollback_sub` | 1. Полный жизненный цикл сервера подписок.<br>2. ## 🏗 Архитектура тестового стенда

Для тестов обслуживания в `tests/docker-compose.test.yml` выделен отдельный изолированный стек контейнеров (**STACK 7**):

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ Выделенный стек STACK 7 (Maintenance)                                       │
│                                                                             │
│  ┌───────────────────────┐  ┌───────────────────────┐  ┌──────────────────┐ │
│  │ vps-maint-panel       │  │ vps-maint-recovery    │  │ vps-maint-sub    │ │
│  │ • SSH порт: 2261      │  │ • SSH порт: 2262      │  │ • SSH порт: 2263 │ │
│  │ • TLS порт: 8481      │  │ • TLS порт: 8482      │  │ • TLS порт: 8483 │ │
│  │ • HTTP порт: 8061     │  │ • HTTP порт: 8062     │  │ • HTTP порт: 8063│ │
│  │ • Исходный стенд      │  │ • Чистый стенд под    │  │ • Стенд сервера  │ │
│  │   панели для бэкапа   │  │   recovery-миграцию   │  │   подписок       │ │
│  └───────────────────────┘  └───────────────────────┘  └──────────────────┘ │
└─────────────────────────────────────────────────────────────────────────────┘
```

Изоляция стека обслуживания исключает влияние потенциально деструктивных операций (перезагрузка, откат, переустановка контейнеров) на параллельно выполняющиеся тесты деплоя и VPN связности.

## ⚙️ Допущения и адаптации для DinD

### 1. Скачивание и валидация архивов по SCP
- В процессе выполнения бэкапа (`deploy_mode: backup` и `deploy_mode: backup_sub`) удалённый скрипт архивирует рабочий каталог в `/root/backup_*.tar.gz`.
- `ssh_deployer` загружает архив на локальный хост в директории `./backups_panel/` или `./backups_sub_server/` через SCP.
- В тестах архивы открываются встроенным модулем Python `tarfile` для верификации обязательных файлов:
  - Панель: `3x-ui/db/x-ui.db`, `caddy/Caddyfile`, `nginx-decoy/html/index.html`.
  - Саб-сервер: `nodes.json`, `force-subs.yml`, шаблоны Caddy и Decoy.
- После окончания тестов скачанные локальные архивы удаляются в блоках `finally`.

### 2. Восстановление с автозаменой домена (Domain Migration)
- При восстановлении из бэкапа на `vps-maint-recovery` передаётся новый домен `maint-recovery.test`, отличный от исходного `maint-panel.test`.
- Скрипт восстановления автоматически выполняет замену доменного имени во всех конфигурационных файлах Caddy, Nginx Decoy и базах данных.
- В DinD тест проверяет, что Caddy на новом сервере успешно поднимается и отвечает по новому доменному имени с самоподписанным сертификатом (`local_certs`).

### 3. Симуляция перезагрузки сервера (`restart_server`)
- В реальной системе команда `restart_server` вызывает бинарник `reboot`.
- Внутри Docker-контейнера выполнение физического ребута гостевого ядра невозможно без привилегий хостовой системы. В скриптах обслуживания команда перезагрузки отправляет сигнал перезапуска сервисов/демона, а тестовый раннер ожидает кратковременного разрыва и успешного восстановления соединения по SSH.

### 4. Тестирование отката саб-сервера (`rollback_sub`)
- Чтобы проверить устойчивость процедуры отката к реальным сбоям:
  1. Создаётся эталонный бэкап саб-сервера.
  2. Файл `nodes.json` на удалённом сервере намеренно повреждается (записывается невалидный JSON либо удаляются все записи о нодах).
  3. Запускается операция `rollback_sub` с указанием ранее созданного архива.
  4. Тест проверяет, что `nodes.json` восстановился до исходного валидного состояния и `subs-server` снова корректно отдаёт подписки.

### 5. Независимость внутреннего `dockerd`
- Каждый VPS-контейнер обслуживающего стека монтирует свой независимый именованный Docker volume (`vps-maint-panel-docker`, `vps-maint-recovery-docker`, `vps-maint-sub-docker`).
- Это гарантирует сохранение состояния сервисов между переподключениями SSH и имитирует постоянный диск реального VPS.

## 🚀 Запуск тестов

```bash
# Запуск всех тестов обслуживания параллельно
./tests/maintenance/run_maintenance_tests.sh

# Запуск отдельных тестов
python3 tests/maintenance/test_maint_panel_backup_recovery.py
python3 tests/maintenance/test_maint_sub_server.py
python3 tests/maintenance/test_maint_panel_update.py
python3 tests/maintenance/test_maint_panel_restart.py
```
